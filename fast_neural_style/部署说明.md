# Ti60 风格迁移部署说明

训练、校准及转换命令见[使用说明](使用说明.md)。默认模型是 `dw_c4_s`
（`ti60_style_dw_c4_s_v1`），不是历史 `bn_3x3`。本轮新增 `bn_c8_r2` 压缩候选，
最低目标调整为 RGB 640x480、30 fps；60 fps 仅保留为对照预算。
当前没有端到端板测证明，软件报告必须保留 `hardware_proven: false`。
本次仅修改当前工作区内训练、转换代码及文档，没有执行脚本、测试、生成器、综合或板端程序，
也没有修改外部工作区。

## BN-C8-R2 训练侧候选与部署边界

画质基线为 `bn_3x3 --width 0.25` 的 128x128 检查点。新增
`ti60_style_bn_c8_r2_v1` 仅改变训练/转换侧：C4/C8 两级下采样、两个 C8 残差块，
两次最近邻 2x 上采样后分别接 3x3 C4 和线性 RGB 卷积。只使用普通 3x3 Conv、Add、
Resize，固定图为 8 Conv / 2 Add / 2 Resize；残差第二个卷积和 RGB 头保持线性。
BN 折叠、SAME_UPPER、逐通道权重量化和 Resize 量化规则与旧 BN 一致。

VGA 下 113,356,800 MAC/帧；30 fps 需要 3.400704 GMAC/s 的纯卷积吞吐，
不是硬件能力。逻辑 INT8 卷积权重 3,096 字节、INT32 bias 204 字节，不含量化表和
FlatBuffer 元数据。最大完整 INT8 激活为 1,228,800 字节；单个 RGB 输入/输出各
921,600 字节，不能因权重很小就宣称完整帧可放入 Ti60 片上 RAM。

本次不修改 `/home/fin-resect/Program/FPGA/Iris` 下的任何固件、RTL、模型数组、
Generator 配置或板端产物，不启动综合/部署。相同算子名称不代表新图能直接替换旧图：
旧固件的模型 ID、尺寸、算子计数、权重打包、通道/行缓存约束和 arena 都需重新核对。
例如已记录的 Rain 行缓存后端支持的是原模型的 C3/C8/C16/C32、128x128 路径，
其成绩不能直接证明本候选 C4/VGA 能运行，更不能用于保证 30 fps。
先验证新模型的 FP32 画质，再转换校准并独立测量内存、完整 FPGA 资源/时序与新帧率。
`hardware_proven` 始终保持 false，软件图审查通过不代表板端达到目标。

## 默认 DW 模型与历史预算

默认拓扑为 7 DW、9 PW、2 次最近邻 2x Resize、0 ADD，共 16 个卷积模块。
两个 stride=2 DW 下采样后，在四分之一高宽执行 4 组主体可分离卷积和 1 组压缩可分离卷积，
再接一个 PW、两次 2x Resize 和线性 RGB PW。除 RGB 输入输出外，特征均为 C4。
上采样后没有空间处理，输出具有 4x4 重复块；先评估画质，再投入硬件集成。

| 指标 | 数值与含义 |
|---|---|
| VGA 卷积 MAC/帧 | 12,979,200，不含 Resize、DMA、外存与边界处理 |
| 60 fps 卷积吞吐需求 | 0.778752 GMAC/s，是需求而非硬件测量 |
| 60 fps 整条流水线预算 | 每帧约 16.67 ms，必须计入全部阶段与同步 |
| Ti60 资源上限 | 60,800 XLR、256 M10K、160 DSP，片上存储约 320 KiB |

不根据运算峰值推算理想硬件 FPS，不声明未经测量的权重大小或 tensor arena。
转换默认使用检查点尺寸，128/256 检查点必须显式使用 `--height 480 --input-width 640`
覆盖后重新导出、校准及审查。仅在 eval 使用 VGA 或修改产物名称不会改变部署模型尺寸。

旧版 `bn_3x3` 的元数据、检查点及转换产物仍受支持，但契约必须独立：
旧版为 16 个 CONV_2D、5 个 ADD、2 个 Resize；新训练须显式指定
`--architecture bn_3x3 --width 0.25`。旧版成功记录不能证明 DW 成功。

## 转换验收

复用已有转换环境，使用真实内容图 100 至 300 张校准，在 CPU 上同时设置
`CUDA_VISIBLE_DEVICES=-1 TF_ENABLE_ONEDNN_OPTS=0`。完整命令及输出路径见使用说明。
转换器已增加矩形参数、DW 审查和 `compute` 报告；本次没有运行，仍需在服务器实际转换并验证。

| 检查项 | 默认 DW 必须满足 |
|---|---|
| 图拓扑 | 7 DEPTHWISE_CONV_2D、9 CONV_2D、2 RESIZE_NEAREST_NEIGHBOR，无 ADD |
| 布局与类型 | batch=1，静态 NHWC，INT8 输入输出、INT8 权重、INT32 bias |
| DW | depth_multiplier=1、dilation=1，对称逐通道权重量化，权重轴 3 |
| 普通 Conv/PW | 对称逐输出通道权重量化，权重轴 0；PW 为 1x1 stride=1，SAME 或等价 VALID |
| 权重量化 | zero point 为 0；bias 的 scale 与输入及逐通道权重 scale 一致 |
| stride=2 边界 | SAME_UPPER，偶数输入右、下各补 1；填充值为输入激活 zero point |
| 最近邻 | 每次高宽放大 2，align_corners=false、half_pixel_centers=false |
| Resize 量化 | 输入输出 scale、zero point 一致，直接复制 INT8 编码 |
| 输出 | 最终 RGB PW 为线性，无额外 ReLU 或模型内 clamp |

ReLU 应融合进相应卷积。独立 PAD、TRANSPOSE、浮点张量、归一化及其他不支持算子应阻塞。
连续两次最近邻 Resize 可能被转换器合并；当前固定拓扑要求保留两个 2x 节点，
若被融合成一个 4x 节点必须拒绝，解决导出问题后重转，不能绕开图审查。

报告应核对 `status`、`blockers`、`audit`、`compute`、`verification`、`hardware_proven`
和 `artifacts`。`compute` 应列出每层形状、权重数量、MAC、总 MAC 和目标速率需求，
不能把目标速率写成预测 FPS。缺失字段或仍按旧拓扑审查表示适配未完成。
软件通过时状态为 `software_checks_passed_hardware_unproven`、`blockers: []`、
`hardware_proven: false`；生成文件或只打印 `Report:` 均不能代替验收。

`--experimental-folding-atol` 仅用于研究 BN 折叠误差后继续进行软件转换，默认关闭。
实验完成状态为 `experimental_conversion_completed_hardware_unproven`，退出码 3；
必须同时检查 `mode`、原严格 `parity` 和 `folding_experiment`，不能因为 `blockers: []`
就把实验产物认定为严格验收通过，更不能据此部署或宣称硬件性能。
FP64 等价性、ONNX/SavedModel 校验及 INT8 图审查不会随实验预算放宽。
额外的 `--experimental-fused-fp64-reference` 会显式改变实验 ONNX/SavedModel 的参考基准，
但保留原容差、原 FP32 失败记录和实验退出码 3。参考来自实际 FP32 导出参数的 FP64 副本，
不是另一套重新折叠的参数；须检查 `fp64_reference` 的三组参数验证和后续对照。
这种模式同样不能替代原严格验收或硬件证明，INT8 图契约不变。

## TinyML 与 Iris 接入

以原版 TinyML **STANDARD** 实现为目标，不能假定普通卷积驱动已能执行 DW。
下列名称用于在实际 Iris 源码中定位集成点，不是假定已存在的新接口。
实际 Iris 集成点为 `firmware/tinyml_style/src/main.cc` 的 resolver；同目录的
`model_contract.h`、`model_config.h`、`iris_profiler.h`，以及
`overrides/tensorflow/lite/kernels/internal/reference/integer_ops/` 下的驱动分发守卫。
以上用于在 Iris 固件源码目录定位，不是本工作区要修改的文件。
这些均为后续外部工程修改说明，本次没有对外部工程应用补丁。

1. 在 Iris resolver 中注册模型实际使用版本的 CONV_2D、RESIZE_NEAREST_NEIGHBOR，
   DW 模型另需 DEPTHWISE_CONV_2D，旧 BN 和 BN-C8-R2 均需 ADD；注册成功还需确认实现走硬件。
2. 在 Depthwise 内核的任何 CPU 逐元素执行之前加入严格硬件守卫，核对 multiplier、
   dilation、stride、padding、量化轴、融合激活和算子版本。硬件路径缺失或参数不支持时
   必须立即失败，不能先执行 CPU 再记录警告，也不能静默进入参考内核。
3. 同步 `model_contract` 的架构 ID、固定拓扑、尺寸、类型、量化及 Resize 选项。
   使部署检查与转换报告一致，同时独立保留旧 BN 合同。
4. 复用已有的 `iris_resize.cc` 和两级最近邻 2x 硬件路径，核验当前生成配置启用 C4，
   并保持 DMA、缓存管理及输入输出量化参数一致。
   边界 RGB 缩放/裁剪、量化、显示反量化与截断也要放入硬件数据路径。
5. 更新 profiler，分别记录 DW、PW、Resize、DMA、边界处理、同步及整体 Invoke，
   标记实际执行后端，核实没有逐像素/逐元素 CPU 回退。
6. 更新 Generator 配置并重新生成实际硬件与匹配驱动，再综合、布局布线和下载验证。
   生成物与模型合同、软件头文件必须同版，不能只替换 TFLite 文件。
7. 检查主程序各模型独立的使能标志和模型选择分支；新产物不会自动启用对应模型。

输入量化使用实际 scale 和 zero point：
`q = clip(round(pixel / scale + zero_point), -128, 127)`。
输出使用 `pixel = (q - zero_point) * scale`，显示时再截断到 0..255。
不能硬编码加减 128；padding 的实数零也必须编码为对应输入激活 zero point。
RISC-V 仅负责调度、地址、DMA 配置与同步。

## 配置与板端测量

建议先比较 STANDARD 4x2 和 8x2 输入/输出并行配置，记录实际频率、资源、带宽和各层耗时。
不根据截图推荐未经支持验证的 32x1，也不假定更大并行度一定适用 DW。
历史 16x4 设计达到 75,945 XLR、281 RAM，超过 Ti60 容量，应避免作为起点。
整机还需计入 SoC、DMA、外存控制器、视频接口、Resize 和缓冲，片上资源不能只统计卷积核。

历史原版 128x128 Rain 模型在厂商 8x2、100 MHz 配置下 Invoke 为 354.55 ms，
有效卷积吞吐约 0.453 GMAC/s。该数据来自另一模型，不是 DW 的性能预测，
也不能外推本方案已达到 VGA 60 fps。

板测应留存模型与报告版本、Generator 配置、综合/布局布线资源和实际时钟，并完成：

- 多张真实输入的硬件 INT8 输出与软件参考对比，覆盖 padding、量化、Resize 与线性输出。
- profiler 各算子硬件执行证据；仅有 resolver 注册或总 Invoke 时间不足以排除 CPU 回退。
- 外部 RAM、tensor arena、临时缓冲和视频帧缓存的实际峰值、带宽及 DMA/cache 一致性验证。
- 稳态连续帧的摄像头输入到显示输出延迟、吞吐、同步和丢帧记录，本轮核对 VGA30 约 33.33 ms 的整体预算。

软件通过、资源能放下、单次 Invoke 正确和完整视频链路达到 30 fps 是不同验收项，
应分别记录证据；硬件未证明之前不得宣称 30 fps，也不得外推 60 fps。
