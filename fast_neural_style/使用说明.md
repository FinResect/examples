# Ti60 风格迁移训练与转换

本版本面向 Ti60F225I3 的 TinyML 部署准备模型。默认架构为 `dw_c4_s`，
检查点标识为 `ti60_style_dw_c4_s_v1`。默认训练尺寸仍为 128x128，下面示例使用
256x256；目标 B 为 640x480、60 fps，尚未在硬件上证明。
训练使用 BatchNorm，推理和导出前折叠进卷积；不使用反射填充。

默认网络为 7 个 3x3 DW、9 个 1x1 PW、2 个最近邻 2x Resize，无 ADD，
共 16 个卷积模块。除 RGB 输入输出外，特征通道均为 C4：第一个 DW 在 RGB 三通道上执行，
两个下采样 DW 的 stride 均为 2，各接一个 PW；随后在 1/4 高、1/4 宽上执行
4 组主体 DW+PW 和 1 组压缩 DW+PW，再执行一个额外 PW、两次 2x 上采样，最后用线性 PW 输出 RGB。
最后一层无 ReLU，训练输出不做 clamp，只有预览保存时截断到 0..255。

**画质限制：两次上采样之后只有逐点 RGB 映射，没有空间卷积，因此浮点输出天然是
4x4 重复块。** 提高输入分辨率不会消除这个结构限制，应先确认画质是否可接受。

软件生成模型不代表板端已完成适配。Depthwise 注册、严格分发和现有最近邻硬件的 C4 路径仍需核验，
完整设计的资源、时序及 RISC-V 无逐元素计算路径必须在板端验证，详见[部署说明](部署说明.md)。

## 环境与数据

以下命令均供服务器端执行，从 `fast_neural_style` 目录运行；本次文档修改没有执行这些命令、
脚本或测试。本地默认环境缺少训练和转换所需依赖，不能据此宣称模型或转换已验证。
复用已有且版本匹配的训练/转换环境即可，无需因文档更新重建环境。
推荐 Python 3.10 或 3.11；先根据服务器驱动安装匹配的 CUDA PyTorch/torchvision，再安装：

```bash
python -m pip install -r requirements.txt
```

`--accel` 使用 CUDA；不传则使用 CPU。首次训练会由 torchvision 下载 ImageNet VGG16
权重以计算感知损失。离线服务器需提前准备对应 torch hub 缓存，可通过 `TORCH_HOME`
指定缓存目录。VGG 只参与损失计算，不会导出到部署模型。

训练集采用 ImageFolder 格式，至少包含一层子目录，类别标签不会用于训练：

```text
/data/content/
  images/
    0001.jpg
    0002.png
```

训练、图片推理和校准使用 RGB、PIL bilinear 缩放、中心裁剪、像素值 0..255。
正方形按短边缩放；矩形按覆盖目标高宽的比例缩放后中心裁剪。
模型输入本身不做 ImageNet 标准化；该标准化只用于 VGG 损失。

## 服务器训练

```bash
python neural_style/neural_style.py train \
  --dataset /data/content \
  --style-image images/style-images/mosaic.jpg \
  --save-model-dir outputs/models \
  --checkpoint-model-dir outputs/checkpoints \
  --architecture dw_c4_s \
  --image-size 256 \
  --batch-size 4 \
  --epochs 2 \
  --workers 4 \
  --accel
```

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--architecture` | dw_c4_s | 固定 C4 的 DW/PW 网络；旧版选择 bn_3x3 |
| `--width` | 仅旧版使用 | dw_c4_s 不接受此参数；旧版 Ti60 使用 0.25 |
| `--image-size` | 128 | 正方形边长，至少 16，且为 4 的倍数 |
| `--image-height`、`--image-width` | 不指定 | 必须成对提供，每边至少 16 且为 4 的倍数；与 image-size 互斥 |
| `--style-size` | 跟随内容目标高宽 | 提供时使用指定边长的正方形风格图 |
| `--batch-size` | 4 | BN 统计质量与批大小有关，优先使用稳定且足够的批大小 |
| `--epochs` | 2 | 仅初始设置，不保证收敛或风格质量 |
| `--content-weight` | 1e5 | 内容损失权重 |
| `--style-weight` | 1e10 | 风格损失权重 |
| `--lr` | 1e-3 | Adam 学习率 |
| `--workers` | 4 | 数据加载进程数；环境不支持多进程时设 0 |
| `--log-interval` | 100 | 每多少个 batch 打印损失 |
| `--checkpoint-interval` | 2000 | 每多少个 batch 保存中间权重 |

训练 VGA 矩形时，将上面命令的 `--image-size 256` 替换为
`--image-height 480 --image-width 640`，不能同时保留正方形选项。
当前训练只有既有 VGG 内容/风格损失，没有 QAT、教师蒸馏或优化器断点续训。

每个 epoch 保存 `ti60_epoch_<epoch>_<时间>.model`，例如
`outputs/models/ti60_epoch_2_TIMESTAMP.model`。文件包含 `metadata` 和 `state_dict`，
保留完整 BN running mean/variance，不包含优化器状态。推理从元数据读取架构和尺寸。
可在服务器运行 `python script/para.py --model outputs/models/ti60_epoch_2_TIMESTAMP.model`
查看实际参数量；该统计不将 BN running statistics 计作可训练参数，不能当作部署权重字节数。

旧版 `bn_3x3` 仍支持，其标识为 `ti60_style_bn_3x3_v1`，8/16/32 通道、5 个残差块。
重新训练旧版必须显式使用 `--architecture bn_3x3 --width 0.25`，替换上述 architecture 选项。
已有带元数据的 BN 检查点及对应旧版转换产物仍按旧版契约使用，不能冒充 DW 模型。
原始 InstanceNorm 权重、裸 state_dict 和折叠后的权重不能冒充训练检查点。

先查看新模型图片效果，再进行 INT8 校准。风格不足可调整 style-weight，内容丢失可调整
content-weight；损失调整无法消除上述 4x4 重复块限制。

## 图片推理

```bash
python neural_style/neural_style.py eval \
  --model outputs/models/ti60_epoch_2_TIMESTAMP.model \
  --content-image images/content-images/amber.jpg \
  --output-image outputs/preview.png
```

默认使用检查点的训练尺寸，可用 `--image-size 256` 覆盖正方形尺寸。
VGA 预览示例：

```bash
python neural_style/neural_style.py eval \
  --model outputs/models/ti60_epoch_2_TIMESTAMP.model \
  --content-image images/content-images/amber.jpg \
  --image-height 480 --image-width 640 \
  --output-image outputs/preview_vga.png
```

矩形参数必须成对提供，并与 `--image-size` 互斥。`--architecture` 可省略，由检查点决定；
提供时检查一致性。`--width` 仅用于旧版 BN 的一致性检查，不用于 DW 模型。
`--export-onnx outputs/style.onnx` 可额外导出固定尺寸、折叠 BN 的 ONNX（需安装 ONNX 依赖）。
eval 不直接加载 ONNX，也不提供旧的 `--content-scale` 路径。

## 转换与校准

建议在已有独立转换环境安装或核对：

```bash
python -m pip install -r requirements-convert.txt
```

依赖版本范围是候选约束，尚未在本地完整验证。TensorFlow、tf-keras、onnx2tf 需要匹配版本；
服务器验证成功后使用 `pip freeze` 留存实际环境。

校准目录可递归包含 jpg/jpeg/png，大小写后缀均支持。使用与实际摄像头或内容输入相近的
100 至 300 张真实内容图，不要用随机噪声代替。脚本按路径排序取前 N 张，目录应有代表性。

以下为目标 VGA 转换命令。**转换默认取检查点尺寸；从 128/256 训练检查点部署 VGA 时，
必须显式覆盖为 480x640，不能只改文件名。**

```bash
CUDA_VISIBLE_DEVICES=-1 TF_ENABLE_ONEDNN_OPTS=0 python script/model2tf_lite.py \
  --model outputs/models/ti60_epoch_2_TIMESTAMP.model \
  --height 480 --input-width 640 \
  --calib /data/calibration \
  --calib-count 100 \
  --onnx outputs/style.onnx \
  --saved-model outputs/saved_model \
  --int8-tflite outputs/style_int8.tflite \
  --content images/content-images/amber.jpg
```

`--height` 与 `--input-width` 必须成对，且与正方形 `--size 256` 互斥；每边至少 16 且为
4 的倍数。两类覆盖均不提供时使用检查点尺寸。转换器的 `--width` 仅用于旧版 BN 通道倍率
一致性检查，不是输入图像宽度，也不能用于给 DW 网络调宽。

转换脚本已增加 DW/VGA 参数、按架构审查和计算量报告，但本次没有执行转换。
服务器使用时应核对新架构及实际输入形状，不能将旧版成功报告用于 DW。

推荐转换时禁用 GPU 并关闭 oneDNN 优化，使 CPU 上的 PyTorch 与 TensorFlow 结果便于比较。
环境变量仅作用于本次命令及子进程，不影响 CUDA 训练。历史服务器曾在 TensorFlow GPU 路径
出现 SavedModel parity 超限，同时禁用 GPU 和 oneDNN 后旧版转换完成；不能单独归因于其中
某一项，也不能据此认定 DW 转换已经通过。无需因此重新训练或放宽校验阈值。

沿用 one_last_kiss 产物名称的服务器示例，同样必须明确 VGA 尺寸：

```bash
CUDA_VISIBLE_DEVICES=-1 TF_ENABLE_ONEDNN_OPTS=0 python script/model2tf_lite.py \
  --model outputs/models/ti60_epoch_2_TIMESTAMP.model \
  --height 480 --input-width 640 \
  --calib images/calib \
  --calib-count 100 \
  --onnx outputs/onnx/one_last_kiss_0.onnx \
  --saved-model outputs/saved_model \
  --int8-tflite outputs/one_last_kiss_0_int8.tflite \
  --content images/content-images/cobi.jpg
```

在 bash/zsh 中，续行反斜杠 `\` 必须是该行最后一个字符，后面不能有空格。
转换固定 batch=1、INT8 输入输出、NHWC。每次在 `--saved-model` 下创建新的 `run-*` 目录
保留中间结果，不复用不匹配的图。

转换依次核对未折叠模型与折叠模型、ONNX、SavedModel 的结果，在真实图片、固定随机输入、
零输入上以 `atol=0.01, rtol=0.0001` 检查。量化前布局来自 SavedModel 实际签名。
ONNX 阶段简化常量图，将可证明等价的零 PAD 合入卷积，并核验静态 SAME_UPPER 边界；
最终仍须审查 TFLite，不能只检查 ONNX。

输出包括：

- `style_int8.tflite`：候选部署模型，生成文件不等于审查通过。
- `style_int8.tflite.report.json`：算子选项、量化、审查、计算量、数值验证及阻塞项报告。
- `style_int8.tflite.preview.png`：审查通过后生成的量化预览；未传 content 时使用首张校准图。

可用 `--report` 和 `--output-image` 更改报告及预览路径。DW 固定拓扑应保留
7 个 DEPTHWISE_CONV_2D、9 个 CONV_2D、2 个 RESIZE_NEAREST_NEIGHBOR，0 个 ADD；
ReLU 融合进卷积。旧 BN 才使用 16 个 CONV_2D、5 个 ADD、2 个 Resize 契约。
转换器可能把连续两次最近邻上采样合并为一次 4x；本契约仍要求保留两个 2x 节点，
这种输出应被拒绝，不能绕过固定拓扑审查。独立 PAD、TRANSPOSE、归一化或浮点张量也会阻塞。

DW 要求 depth_multiplier=1、dilation=1、对称逐输出通道权重量化，TFLite 权重轴为 3；
普通 Conv 的轴为 0。输入输出 INT8、偏置 INT32，权重 zero point 为 0。
逐点 1x1 stride=1 卷积接受 SAME 或等价的 VALID；3x3 DW 必须为 SAME。
stride=2 使用 SAME_UPPER，偶数尺寸右侧和底部各补 1；量化填充值是输入激活 zero point，
不能直接填整数 0。最近邻必须 `align_corners=false`、`half_pixel_centers=false`，
输入输出 scale 和 zero point 相同。

退出码 0 表示软件检查通过，报告状态为 `software_checks_passed_hardware_unproven`，
仍不是硬件可用证明。转换或审查失败退出 1 并写入 blocker；命令行参数或输出路径冲突
退出 2。失败后先查看报告，不要绕过审查部署。

### 查看转换结果

针对上面的 one_last_kiss 命令，在服务器运行：

```bash
python -c 'import json; r=json.load(open("outputs/one_last_kiss_0_int8.tflite.report.json")); print(json.dumps({k:r.get(k) for k in ("status","blockers","audit","compute","verification","hardware_proven","artifacts")}, indent=2, ensure_ascii=False))'
```

成功状态示例，仅展示部分字段；`audit`、`compute`、`verification` 仍需查看实际完整报告，
缺失字段不能当作检查通过：

```json
{
  "status": "software_checks_passed_hardware_unproven",
  "blockers": [],
  "hardware_proven": false
}
```

| 字段 | 必须核对的内容 |
|---|---|
| `audit` | 固定拓扑、实际算子版本/选项、张量形状与量化契约 |
| `compute` | 每层形状、权重数量及 MAC、总 MAC、目标帧率对应的运算需求；不输出理想硬件 FPS |
| `parity` / `verification` | 前者记录浮点各阶段一致性，后者记录浮点与 INT8 图片误差及饱和比例 |
| `hardware_proven` | 软件转换后仍为 false；板端证明须有独立实测记录 |

| 文件 | 用途 |
|---|---|
| `outputs/one_last_kiss_0_int8.tflite` | 候选 INT8 部署模型 |
| `outputs/one_last_kiss_0_int8.tflite.report.json` | 数值检查、算子审查、计算量与量化信息 |
| `outputs/one_last_kiss_0_int8.tflite.preview.png` | 量化后的风格迁移预览 |

查看预览，并结合 `verification.float_vs_int8_clipped_0_255` 的 MAE、RMSE、PSNR、
输入截断比例、输出整数边界占比判断量化影响。单张图片不代表全部输入质量。

### 常见日志

| 日志 | 解释 |
|---|---|
| `CUDA_ERROR_NO_DEVICE` | 禁用 GPU 后可能出现探测失败；若后续 CPU 转换继续，并非失败依据 |
| `Unable to register cuFFT/cuDNN/cuBLAS factory` | 插件重复注册提示；是否失败看后续异常、退出码和报告 |
| `Ignored output_format / drop_control_dependency` | 转换器提示，不单独表示失败 |
| LiteRT interpreter migration warning | 解释器迁移提醒，以当前转换报告判定 |
| `fully_quantize: 0` | 不能据此认定浮点回退，以最终 dtype 和算子审查为准 |
| `pytorch_fused_vs_saved_model_* parity failed` | 先使用 CPU 命令复查误差和布局，不能直接跳过 |

输入量化：`q = clip(round(pixel / scale + zero_point), -128, 127)`。
输出反量化：`pixel = (q - zero_point) * scale`，仅预览/显示时截断到 0..255。
不能固定减/加 128；INT8 编码范围不代表输入输出 zero point 固定在边界。
报告不宣称普适精度阈值，风格质量还需多张验证图片人工检查。

## 硬件部署边界

目标是 RISC-V 只做调度、地址设置、DMA 配置及同步，所有逐像素/逐元素处理在硬件数据路径。
采用原版 TinyML STANDARD 路径，补齐 DW、最近邻 Resize、边界 RGB 转换和严格硬件分发；
当前主程序中各模型独立的使能标志不会因生成新模型而自动打开。
Iris resolver、Depthwise 的 CPU 执行前严格守卫、`model_contract`、profiler 和 Generator
重新生成流程都需同步，具体步骤见[部署说明](部署说明.md)。这些是外部集成工作说明，
本次没有修改外部 Iris 工作区。

| 项目 | 目标 B：640x480、60 fps |
|---|---:|
| 默认 DW 卷积 MAC/帧 | 12,979,200 |
| 仅卷积所需持续吞吐 | 0.778752 GMAC/s |
| 整条流水线每帧预算 | 约 16.67 ms |

MAC 不含 Resize、DMA、外存访问、量化、视频输入输出及同步开销；不能从 MAC 直接推导
硬件 FPS，也不在此声明未实测的权重大小、tensor arena 或整机资源。
Ti60 总资源为 60,800 XLR、256 M10K、160 DSP，片上存储约 320 KiB；
主要张量、视频帧缓存和权重的存放必须结合外部 RAM 与实测分配规划。
推荐从 STANDARD 4x2 或 8x2 配置测量，完整资源、时序及帧率以综合、布局布线和板测为准。

历史原版 128x128 Rain 模型在厂商 8x2、100 MHz 下 Invoke 为 354.55 ms，
有效卷积吞吐约 0.453 GMAC/s。这是另一网络的测量，不能预测 DW 性能，更不能证明 60 fps。
历史 16x4 配置达到 75,945 XLR、281 RAM，超过 Ti60 容量，不适合作为本方案起点。
