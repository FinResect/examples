# Ti60 风格迁移训练与转换

本版本面向 Ti60F225I3 的 TinyML 部署准备模型。默认 `--width 0.25`、
128x128 RGB 输入输出、8/16/32 通道、全 3x3 卷积、5 个残差块。
训练使用 BatchNorm，推理和导出前折叠进卷积；反射填充已移除。
这是新的架构，必须重新训练，仓库中原有 InstanceNorm 权重不能加载。

软件生成模型不代表板端已完成适配。最近邻上采样仍需要 FPGA 模块和算子分发接入，
完整设计的资源、时序和 RISC-V 无逐元素计算路径必须在板端验证。

## 环境与数据

以下命令从 `fast_neural_style` 目录执行。推荐 Python 3.10 或 3.11 的独立环境。
先根据服务器驱动安装匹配的 CUDA PyTorch/torchvision，再安装训练依赖：

```bash
python -m pip install -r requirements.txt
```

`--accel` 使用 CUDA；不传则使用 CPU。首次训练会由 torchvision 下载 ImageNet VGG16
权重以计算感知损失。离线服务器需提前准备对应 torch hub 缓存，可通过 `TORCH_HOME`
指定缓存目录。VGG 只参与损失计算，不会导出到部署模型。

训练集采用 ImageFolder 格式，至少包含一层子目录，类别标签不会用于训练：

```text
/data/content/
  images/
    0001.jpg
    0002.png
```

训练、图片推理和校准使用 RGB、短边缩放到目标尺寸、中心裁剪、像素值 0..255。
缩放为 PIL bilinear。模型输入本身不做 ImageNet 标准化；该标准化只用于 VGG 损失。

## 服务器训练

```bash
python neural_style/neural_style.py train \
  --dataset /data/content \
  --style-image images/style-images/mosaic.jpg \
  --save-model-dir outputs/models \
  --checkpoint-model-dir outputs/checkpoints \
  --width 0.25 \
  --image-size 128 \
  --batch-size 4 \
  --epochs 2 \
  --workers 4 \
  --accel
```

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--width` | 0.25 | Ti60 转换要求此值，即 8/16/32 通道 |
| `--image-size` | 128 | 至少 16，且必须是 4 的倍数 |
| `--style-size` | 跟随 image-size | 风格图同样按短边缩放和中心裁剪 |
| `--batch-size` | 4 | BN 统计质量与批大小有关，优先使用稳定且足够的批大小 |
| `--epochs` | 2 | 仅初始设置，不保证收敛或风格质量 |
| `--content-weight` | 1e5 | 内容损失权重 |
| `--style-weight` | 1e10 | 风格损失权重 |
| `--lr` | 1e-3 | Adam 学习率 |
| `--workers` | 4 | 数据加载进程数；环境不支持多进程时设 0 |
| `--log-interval` | 100 | 每多少个 batch 打印损失 |
| `--checkpoint-interval` | 2000 | 每多少个 batch 保存中间权重 |

每个 epoch 保存 `ti60_epoch_<epoch>_<时间>.model`。模型文件包含 `metadata` 和
`state_dict`，保留完整 BN running mean/variance；不包含优化器状态，不提供断点续训。
架构标识为 `ti60_style_bn_3x3_v1`。推理和转换从元数据读取 width 与尺寸。
不要将旧模型文件、裸 state_dict 或折叠后的权重冒充训练检查点。
可运行 `python script/para.py --model /path/to/model.model` 查看实际参数量；
该统计不将 BN 的 running statistics 计作可训练参数。

BN 与原 InstanceNorm 的行为不同，建议先查看新训练模型的图片效果，再进行 INT8 校准。
风格不足可调整 style-weight；内容丢失可调整 content-weight；不要直接假设旧超参数仍最优。

## 图片推理

python neural_style/neural_style.py eval \

## 转换与校准

建议在独立转换环境安装：

```bash
python -m pip install -r requirements-convert.txt
```

转换依赖中的版本范围是候选约束，尚未在本机完整验证。TensorFlow、tf-keras、onnx2tf
需要匹配版本；服务器验证成功后使用 `pip freeze` 留存实际环境。

校准目录可递归包含 jpg/jpeg/png，大小写后缀均支持。使用与实际摄像头或内容输入相近的
100 至 300 张真实内容图，不要用随机噪声代替校准图。脚本按路径排序取前 N 张，
因此应事先保证校准目录的代表性。

```bash
CUDA_VISIBLE_DEVICES=-1 TF_ENABLE_ONEDNN_OPTS=0 python script/model2tf_lite.py \
  --model outputs/models/ti60_epoch_2_TIMESTAMP.model \
  --calib /data/calibration \
  --calib-count 100 \
  --onnx outputs/style.onnx \
  --saved-model outputs/saved_model \
  --int8-tflite outputs/style_int8.tflite \
  --content images/content-images/amber.jpg
```

推荐在转换时禁用 GPU 并关闭 oneDNN 优化，使 CPU 上的 PyTorch 参考结果与 TensorFlow
结果更便于比较。上述环境变量仅作用于本次命令及其子进程，不影响之前的 CUDA 训练。
服务器曾在 TensorFlow 使用 GPU 时出现 SavedModel parity 超限；同时禁用 GPU 和 oneDNN
后已进入并完成 INT8 转换，但尚不能单独归因于其中某一项。无需因此重新训练或放宽校验阈值。

本次服务器使用的具体命令如下；模型文件名需对应实际训练输出：

```bash
CUDA_VISIBLE_DEVICES=-1 TF_ENABLE_ONEDNN_OPTS=0 python script/model2tf_lite.py \
  --model outputs/model/ti60_epoch_2_20261005_014835.model \
  --calib images/calib \
  --calib-count 100 \
  --onnx outputs/onnx/one_last_kiss_0.onnx \
  --saved-model outputs/saved_model \
  --int8-tflite outputs/one_last_kiss_0_int8.tflite \
  --content images/content-images/cobi.jpg
```

在 bash/zsh 中，续行反斜杠 `\` 必须是该行最后一个字符，后面不能有空格。
否则下一行的 `--model` 等参数可能被当作独立命令执行。

转换固定 batch=1、INT8 输入输出、NHWC。`--size` 默认取检查点尺寸，覆盖时必须至少
16 且为 4 的倍数。移除了旧的 skip、opset、输入输出 dtype 开关，避免复用不匹配的图。
每次会在 `--saved-model` 下创建新的 `run-*` 目录并保留中间结果。

转换依次核对未折叠模型与折叠模型、ONNX、SavedModel 的结果，在真实图片、固定随机输入、
零输入上以 `atol=0.01, rtol=0.0001` 检查。量化前的布局来自 SavedModel 实际签名。
ONNX 阶段先简化常量图，将可证明等价的零 PAD 合入卷积，并根据静态形状核验
SAME_UPPER 边界；数值比较使用此处理后的 ONNX。最终审查 TFLite 而不只检查 ONNX。

输出包括：

- `style_int8.tflite`：候选部署模型，生成文件不等于审查通过。
- `style_int8.tflite.report.json`：算子版本及选项、张量形状、量化参数、文件大小、阻塞项。
- `style_int8.tflite.preview.png`：审查通过后生成的量化输出图，未传 content 时使用首张校准图。

可用 `--report` 和 `--output-image` 更改报告及预览路径。
报告要求 16 个 CONV_2D、5 个 ADD、2 个 RESIZE_NEAREST_NEIGHBOR；ReLU 应融合进卷积。
独立 PAD、TRANSPOSE、归一化、浮点张量等会阻止成功。stride=2 的零填充采用偶数输入下
右侧和底部各补 1 的 SAME 语义；如果转换器未融合为 SAME，报告将拒绝残留 PAD。

退出码 0 表示软件检查通过，报告状态为 `software_checks_passed_hardware_unproven`，
仍不是硬件可用证明。转换或算子检查失败退出 1 并写入 blocker；命令行参数或输出路径
冲突退出 2。失败后先查看报告，不要绕开审查直接部署。

### 常见日志

| 日志 | 解释 |
|---|---|
| `CUDA_ERROR_NO_DEVICE` | 设置 `CUDA_VISIBLE_DEVICES=-1` 后可能出现 GPU 探测失败；若后续 CPU 转换继续，并非本次失败依据 |
| `Unable to register cuFFT/cuDNN/cuBLAS factory` | 可能出现的插件重复注册提示；是否失败看后续异常、退出码和报告 |
| `Ignored output_format / drop_control_dependency` | 转换器提示，不单独表示转换失败 |
| LiteRT interpreter migration warning | 解释器迁移提醒，不影响当前转换结果的判定 |
| `fully_quantize: 0` | 内部日志字段，不能据此认定浮点回退；以最终张量 dtype 和算子审查为准 |
| `pytorch_fused_vs_saved_model_* parity failed` | 浮点一致性检查未通过；先使用上述 CPU 命令复查，仍失败则检查误差与布局，不能直接跳过 |

输入量化：`q = clip(round(pixel / scale + zero_point), -128, 127)`。
输出反量化：`pixel = (q - zero_point) * scale`，然后截断到 0..255。
不能固定减/加 128。报告给出一张图的浮点与 INT8 误差、PSNR 和饱和比例；
没有宣称普适的精度阈值，风格质量还应在多张验证图片上人工检查。

## 硬件部署边界

目标是 RISC-V 只做调度、地址设置、DMA 配置及同步。以下是部署侧尚需完成的工作：

- TinyML Standard Conv 与 Add，核验每通道量化、融合 ReLU、残差重定标和算子版本。
- 自定义 FPGA 最近邻 2x 上采样模块及其软件分发接入。上下采样节点的实际选项以报告为准；
当前模型只有上采样，输入输出 scale/zero point 必须一致。
- 卷积边界的零填充值使用输入 zero point；不能直接写整数 0。
- 输入缩放裁剪、RGB 量化和输出反量化/截断安排在硬件数据路径。
- 每层确认没有逐像素或逐元素的 CPU 回退，完成板端输出对比与性能测量。

Ti60 文档总资源为 60,800 XLR、256 M10K、160 DSP，片上存储约 320 KiB。
初始配置建议 AXI 128 bit、Standard 卷积输入/输出并行度 4/2、Standard Add、
卷积相关 FIFO 参数 512、Cache depth 256，其余未使用的独立算子加速器关闭。

按仓库 TinyML Generator 公式估算，卷积/Add/Cache/公共模块合计约 16,800 LUT、
11,714 FF、3,442 ADD、57 M10K、24 DSP。它不包含 SoC、DMA、外存控制器、视频接口或新增
上采样模块；LUT/FF/ADD 不能直接相加成 XLR。整机资源必须通过综合与布局布线确认，
建议保留约 15% 余量，时钟与帧率以实际测量为准。

| 项目 | 128x128 | 256x256 |
|---|---:|---:|
| 卷积 MAC/帧 | 148,635,648 | 594,542,592 |
| 最大中间特征张量（含上采样输出，INT8） | 256 KiB | 1 MiB |

卷积权重为 104,112 个 INT8 值，不含偏置、量化信息和模型元数据。
本方案要求外部 RAM 存放主要张量和权重。128 首版可先预留 2 MiB 工作区，
它只是预算，不是实测 tensor arena；视频帧缓存另计。报告中的最大张量也不代表峰值内存。

## 方案 C：720p60 流水线行缓存知识蒸馏与硬件直出

为了在易灵思 Ti60F225 硬件上严格保证 720p60 输出，同时彻底消除每层中间特征进出外部 DDR3 的吞吐瓶颈，引入了**方案 C（Teacher-Student 知识蒸馏）**。

### 1. 架构原理
- **Teacher 网络（深层大模型）**：标准 16 层 ResNet 结构（`TransformerNet`，包含 5 个残差块，约 10.4 万参数）。它具备极佳的艺术风格、笔触与丰富色彩纹理学习能力。
- **Student 网络（板载流式行缓存小模型）**：3 层流式卷积（`StreamStudentNet`，定义在 `neural_style/stream_net.py`）：
  - 第 0 层：`Conv3s2`（输入 3 通道 RGB 映射为 4 通道，stride=2，下采样为 360p）
  - 第 1 层：`Conv3d2`（4 通道到 4 通道，stride=1，**dilation=2**，空洞卷积扩大感受野以捕捉艺术笔触）
  - 第 2 层：`Conv1s1`（4 通道映射为 3 通道 RGB，1x1 卷积色彩合成）
  - 后处理：最近邻 2x 上采样回 720p 原图。
  - **总参数量仅 275 个 INT8 权重与偏置**，计算量 23.35 MMAC/帧，单帧硬件推理延迟仅 27.9ms（硬件固有 35.8 FPS），配合双相插帧显示流水线平滑输出稳定 720p60，且中间特征**0 DDR 搬运**，全部在 FPGA 内部行缓存流水处理！

### 2. 损失函数设计（解决浅层网络画质发虚）
为了让 3 层学生模型兼具大师风格与清晰轮廓，蒸馏脚本集成了多维复合损失：
1. **$L_1$ 蒸馏损失**：学生输出拟合教师输出的主体色调与画风。
2. **边缘梯度损失（$\Delta_x, \Delta_y$ Sobel 差分）**：强制学生模型重现教师模型的高频边缘、文字轮廓与面部轮廓，彻底消除小网络常见的模糊泛晕。
3. **阴影与暗线加权（$w = 1.0 + 3.0 \times (1.0 - Y)$）**：对黑色勾线与深色面部轮廓给予最高达 4 倍的损失反向权重。
4. **辅助风格感知损失**（可选）：计算 VGG16 Gram 矩阵相似度以强化特定画家的笔触色彩。

### 3. 一键训练与硬件头文件导出命令

蒸馏脚本位于仓库根目录的 `distill_stream.py`。

### 4. 导出产物说明
训练完成后，脚本会自动执行 INT8 激活校准、BN 折叠与 GEMMLowp 定点数转换，生成：
1. `stream_model.h`：包含完全符合 Ti60 RISC-V 固件期望的 `static const uint32_t iris_cnn_parameters[3][52]` 硬件参数数组。

## 方案 3 (Iris-TensorCore: 104,112 参数大模型 8x8 全硬件重构架构)

针对浅层微网络（如 264 参数模型）无法细腻表达莫奈印象派油画笔触与丰富层次感的问题，方案 3 采用了全规模 16 层残差 Transformer 网络与 8x8 矩阵加速重构架构：

### 1. 架构规格与性能
- **模型网络**：`TransformerNet(width=0.25)`
  - 16 层 3x3 卷积 + 5 个残差瓶颈块（ResBlock）+ 2 次 2x 最近邻上采样放大。
  - **参数量：104,112 个 INT8 权重与偏置**（参数量是 3 层网络的近 400 倍，画质与艺术风格表现力呈数量级提升）。
- **硬件矩阵核心**：
  - `iris_rain_conv.v`：8 入 8 出（单周期 64 个 INT8 MAC 计算单元），片上 4 行缓存循环复用，片上专用权重 RAM，DDR 读流量降低 8 倍。
  - `iris_rain_backend.v`：行级重叠 AXI 突发控制器，当前行计算与上一行 DDR 写出并行流水。
  - `iris_rain_add.v`：4 通道并行定点残差加法引擎。
- **实测硬件性能（Ti60F225I3 @ 100MHz）**：
  - **单帧硬件推理延迟仅 31.77 ms（稳定 30.05 FPS 实时 AI 输出）**。
  - 与 TensorFlow Lite 原厂浮点/INT8 黄金参考完全一致，**0 LSB 误差**。
  - 配合双相双缓冲显存控制器（`iris_tinyml_panels`），在 HDMI 屏幕上稳定输出流畅无撕裂的 **60 FPS** 画面。
  - 资源占用：XLR 55,352 / 60,800 (91.0%)，RAM 246 / 256 (余 10 块)，DSP 143 / 160 (余 17 块)，正时序裕量（Setup +0.013ns，Hold +0.026ns）。

### 2. 通用训练与一键导出流程

#### 步骤一：环境就绪校验
```bash
./script/setup_env.sh
```
脚本会自动检查 PyTorch+CUDA 训练环境，并在 `.venv-convert` 隔离环境内准备好 ONNX、TensorFlow、ONNX2TF 与 TFLite 转换链。

#### 步骤二：训练任意艺术风格网络
```bash
# 训练任意风格模型（支持平铺图片目录或标准类别子目录）
./train.sh --dataset images/calib --style-image images/style-images/monet.jpg --name monet --epochs 2
```
参数说明：
- `--dataset`：训练图片集目录（平铺存放图片如 `images/calib/*.jpg`，或标准 ImageFolder 子目录均可）。
- `--style-image`：目标艺术风格图片路径（如 `monet.jpg`、`candy.jpg`、`udnie.jpg` 等）。
- `--name`：模型标识代号（默认为风格图片名）。
- `--epochs`：训练轮数（默认 2）。
- `--batch-size`：批大小（默认 4）。
- `--export`：训练完成后是否自动调用导出工具（默认开启）。

#### 步骤三：一键量化与工程自动部署
若使用 `./train.sh`，训练完成后会自动触发导出与部署；若单独训练了 PyTorch 权重，也可手动执行：
```bash
./export_model.py --model model/<训练产物>.model --name <模型代号>
```
脚本将全自动执行：
1. PyTorch 模型验证与 BatchNorm 卷积折叠。
2. 导出 ONNX 并通过 ONNX2TF 转换为全整型 INT8 TFLite。
3. 运行 `compile-rain-backend.py` 将 INT8 权重重排为 8x8 矩阵加速器硬件格式。
4. 生成 C 数组与硬件参数头文件，自动清理掉占用数十兆的 `saved_model/` 与 `.onnx` 临时目录。
5. 在 `output/<name>/` 中仅保留必要产物，并自动同步部署至 `Iris/model_input/`。

### 3. 板端固件编译与一键极速烧录

模型部署完成后，在 `Iris` 仓库目录下仅需两行命令：

```bash
cd ../../Iris

# 1. 一键编译 RISC-V 固件（自动从 model_input/ 读取模型参数）
.script/build-firmware

# 2. 一键烧录位流至 SRAM 并通过 OpenOCD 加载固件至 DDR3 启动
.script/sync-iris jtag
```
- **烧录过程**：首先极速写入 FPGA SRAM，随后通过 OpenOCD 自动将固件加载入片外 DDR3（`0x00800000`）并启动 RISC-V 核心，控制台自动显示串口输出的实时推理帧率（30.05 FPS）。
- **掉电保持**：如果需要烧录进板载 SPI Flash 掉电保持自启动，执行 `.script/sync-iris jtag_bridge` 即可。
